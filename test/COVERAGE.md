# Invariant coverage map

Each safety/correctness invariant asserted by a design is mapped here to the
named test(s) that prove it, so the mapping stays auditable. See the design docs
under `docs/design/` for the invariant statements.

## Frame retargeting — `docs/design/2026-10-17-routing-and-filing.md` §9

The feature edits the archived (NAS) copy of a frame while the app may still delete
the sole device-side original. The spine: `sha256` is the device anchor;
`archiveHash(f)` (a read of `archive_sha256`) is used at every
archive-side hash comparison; the device is never modified.

## Delete pass yields to the cycle head — `docs/design/2026-10-17-frame-lifecycle.md` §12

`deletePhase` runs as slices bounded by a deadline anchored on the cycle's
listing, so a large backlog does not freeze listing and pulling for its whole
length. Slicing decides only **when a slice stops** and **which eligible row it starts from** —
`deleteOne`'s own decisions, the three-way hash check and every store query are the same with or
without it. The table maps the invariant numbering (1–11) of
`docs/design/2026-10-17-frame-lifecycle.md` §12.9 to the tests that prove each holds; for the three
invariants that section leaves to the regression suite (three-way check, grace,
restore-before-delete), the specific tests are named individually rather than left as "the
regression suite".

| # | Invariant | Test(s) | Package |
|---|---|---|---|
| 1 | Three-way hash check: no hash, digest or verdict is carried across slices; every attempt re-reads the row and re-hashes both copies. | `TestDeleteThreeWayMatchDeletesFrameAndSidecar` (the check itself, which slicing does not touch) and `TestSlicedDrainExactCount` (every NAS copy re-hashes to its recorded sha256 against a real device) | `internal/rig`, `test/integration` |
| 2 | Device identity per delete session: each slice opens its own session and re-confirms before any delete. | `TestIdentityForeignOnLaterSlice` | `internal/rig` |
| 3 | Grace: the cutoff is taken fresh at every slice start; the cursor only reorders an already grace-filtered set. | `TestDeleteGraceNotElapsedNotEligible` | `internal/rig` |
| 4 | Open re-file and supersede intents: read once per slice, with the same fail-closed skip on a read error; a request queued mid-drain is served in the gap before the next slice re-reads the sets. | `TestIntentOpenedBetweenSlices` | `internal/rig` |

## Remote bridge — `docs/design/2026-10-17-remote-sites.md` §12

A remote site reaches a rig's SMB (445), control (4700) and discovery (UDP 4720)
traffic through a pinned tailcat tunnel, and measures pre-delete digests in its own
session. The spine: every verdict and every delete stays in Commander, the remote
holds no authority or state, and a path never becomes part of a rig's identity.

Tests marked `integration && remotetest` run a real tailcat tunnel against the
Samba NT1 container (`make integration`) and are invisible to the default build;
compile them with `go vet -tags integration ./...`.
